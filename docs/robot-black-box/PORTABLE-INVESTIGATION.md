# Portable investigation package

The existing recorder exports signed bundles. This phase packages the already-public six-case synthetic capture suite with the existing contract, verifier, policy and capture-quality modules, original signed receipts, historical public trust and witness heads. It does not implement another signature format or accept arbitrary private evidence directories.

Build a new directory with `node scripts/robot-black-box/portable-export.mjs /tmp/rbb-public-package` (the destination must not exist). Run `node /tmp/rbb-public-package/scripts/robot-black-box/portable-review.mjs /tmp/rbb-public-package > /tmp/rbb-review.json`. Node 22 or later is sufficient: no npm install, commercial console, network, original workspace or private keys. Keep outputs outside the package, since unexpected files invalidate its inventory. `npm run demo:robot-black-box-portable` executes two detached fresh-process reviews and writes public execution evidence.

The checked example is `examples/robot-black-box-portable/executed/review-package`. Adjacent `portability-execution.json` and `review.json` record two executed reviews after deletion of the original assembly directory, with byte-identical reports on restart. Six bundles retain valid cryptographic integrity; four capture-quality outcomes fail and two remain unknown. Authorization remains a separate policy result. This is file transport/review of synthetic cases, not capture from physical robots.

The sorted transport manifest lists file sizes and SHA-256 hashes and is reproducible for the same source/tool bytes. It is unsigned. Obtain its digest through a trusted separate channel before executing supplied code, or use independently trusted verifier code. A malicious publisher can replace both code and manifest; internal consistency is not publisher authentication. Included public keys are historical publisher snapshots, not independently enrolled identities. Profiles are evaluated at original signed receipt times; historical review does not renew expiry or prove current enrollment. An optional final CLI argument supplies a reviewer trust JSON snapshot and produces separate review-time results without changing historical results. Online freshness remains unattested.

Read-only directory intake rejects traversal, symlinks, hardlinks, special files, extra/missing/mismatched files, files above 16 MiB, total bytes above 32 MiB, over 512 files, over 1,024 entries or paths deeper than 16 components. File size and type are checked before reading. No archive extractor is supplied. Review a static copy; concurrent mutation is outside this local profile. Untrusted package code must never be executed merely because its self-supplied inventory matches.

Validation: 10 portability tests cover reproducible assembly, detached-process review, missing/truncated/tampered/extra files, traversal, symlinks, hardlinks, oversized input, repaired-copy recovery and revoked reviewer trust. The full local suite passed 50/50 tests; CI includes these tests but has not been executed remotely. Existing signed fixtures and videos were preserved. Source truth, independent custody, hardware qualification, secure erase and crash survival remain unknown or unassessed.

This closes a bounded local investigation-export step in the aircraft comparison roadmap. General private-case export/redaction, external investigator trust distribution, archive formats, real source acquisition, retention-duration requirements, crash protection, installation approval and formal qualification remain future gates.

## Reviewer-side pin bootstrap

`portable-bootstrap.mjs` is a standalone trusted reviewer tool with only Node built-in imports. Obtain that tool through a trusted channel and keep it outside the package. Obtain the expected SHA-256 of `package-manifest.json` independently of the delivered package, then run:

```sh
node /trusted/reviewer/portable-bootstrap.mjs /path/to/package EXPECTED_SHA256 > /tmp/pinned-review.json
```

Replace `EXPECTED_SHA256` with the separately obtained 64 lowercase hexadecimal characters. Do not derive your acceptance pin from the untrusted incoming package itself. The earlier direct review command is appropriate only once code authenticity has already been established. There is no automatic fallback to the package's own digest: an absent/malformed/wrong pin is rejected before any included module is imported or executed.

The bootstrap first checks manifest bytes against the reviewer pin, then validates every listed file against that pinned inventory and rejects missing/extra/changed files, unsafe paths and links, and oversized inputs using the portable profile limits. It copies checked bytes into a private temporary snapshot and starts the included review tool only from that snapshot. This avoids reopening the mutable input package for imports. The temporary snapshot is removed after execution; outputs stay outside the package. Node loader environment overrides are removed for the subprocess, and review execution has a 30-second timeout and a 4 MiB output bound. This is a byte-identity gate, not a sandbox: independently approved code still runs with the reviewer's process permissions. Review static input copies; an attacker controlling the reviewer tool, OS, process or pin source is outside this local profile.

A coherent rewrite of evidence or verifier code plus the self-supplied manifest fails the original external pin. A malicious self-supplied manifest cannot grant permission to execute its own verifier. No publisher signed seal was added: a same-publisher signature would not solve independent pin distribution or trusted enrollment, and the original evidence already retains its signatures.

`npm run demo:robot-black-box-bootstrap` writes `examples/robot-black-box-portable/executed/bootstrap-execution.json`. Six fresh processes execute clean detached review, two coherent attack rewrites, wrong pin, absent pin and clean-copy recovery. Benign sentinel code remains unexecuted for both coherent rewrites. The bootstrap is copied outside the package and the original assembly is removed before review. Eleven focused tests additionally cover unsafe/traversal/linked/oversized/missing/extra intake and recovery. The full local suite passed 61/61 tests (previous 50 preserved); CI includes the new tests but has not run remotely.

**Pin provenance limitation:** the local demonstration generated its expected digest on the same host. Its execution record explicitly says `same_host_demo_generated_not_independently_obtained`. This demonstrates pre-execution rejection and reproducibility, not actual independent acquisition of a pin. A real reviewer must establish the pin and bootstrap authenticity independently. Matching a reviewer-supplied pin proves bytes match that pin; it does not by itself establish publisher identity, current enrollment, online freshness, external custody, physical source truth or crash qualification.

## Local custody and restored review

A separately keyed local custodian can now accept the fixed public package transactionally and restore it after the assembly copy is removed. Receipt verification requires an explicit custodian public-identity pin outside the included package; restored evidence is then checked separately by the trusted bootstrap. Ten fresh custody processes exercised pre/post-commit interruption/retry, tampered/missing custody content, altered receipts, wrong identity and clean restore. Nine added tests bring the local suite to 70/70. All keys and pins remain same-host demonstration trust, not independent organizational custody. See [LOCAL-CUSTODY-RESTORE.md](LOCAL-CUSTODY-RESTORE.md) for execution artifacts, pin format, logical-immutability limits and remaining replication/HSM/disaster-recovery gates.

## Custody-store loss recovery milestone

A signed bounded SQLite backup now supports restoration after the original custody database/assembly/private worker configs are removed. Recovery requires separate custodian identity and intended backup-receipt pins, checks bytes before opening the snapshot, validates custody and restores the unchanged package before trusted bootstrap review. The executed same-host isolated-copy drill recovered 47 files/six valid signed cases; all 81 local tests passed. It does not demonstrate off-host replication, host/media-loss recovery, independent pin distribution or production RTO/RPO. See [CUSTODY-BACKUP-RECOVERY.md](CUSTODY-BACKUP-RECOVERY.md).
